# Идеальный AGENTS.md для searxng-mcp-control

Этот документ представляет собой улучшенное видение инструкций для ИИ-агентов (AGENTS.md), работающих в репозитории `searxng-mcp-control`.

## 1. Стек и зависимости
* **Язык программирования:** Python 3.10+
* **Фреймворк/Протокол:** Model Context Protocol (MCP) SDK (FastMCP)
* **Ключевые библиотеки:**
  * `pyyaml>=6.0` — для работы с конфигурациями `settings.yml`. Важно использовать безопасные парсеры (см. Архитектурные особенности).
  * `httpx>=0.24.0` — для асинхронных/синхронных HTTP-запросов (проверки состояния SearXNG).
* **Тестирование:** `pytest`, `pytest-mock`, `pytest-asyncio`, `pytest-cov`.
* **Инфраструктура:** Docker (управление контейнерами через `subprocess.run`).

## 2. Команды верификации
Агенты должны всегда выполнять эти команды перед завершением работы (созданием PR):

* **Установка зависимостей (включая dev-инструменты):**
  ```bash
  pip install -e .[dev]
  ```
* **Запуск тестов с проверкой покрытия:**
  ```bash
  python -m pytest tests/ --cov=searxng_mcp_control
  ```
  *(Минимально допустимое покрытие кода — 95%)*
* **Форматирование и проверка стиля кода (Линтеры):**
  *(Примечание: хотя в pyproject.toml пока не указаны black или ruff, рекомендуется использовать стандартные python инструменты или те, что приняты в экосистеме, например:)*
  ```bash
  black src/ tests/
  flake8 src/ tests/
  mypy src/
  ```

## 3. Архитектурные особенности и правила кодинга
* **Только Backend (No UI):** Это исключительно серверный MCP-проект без пользовательского интерфейса.
* **Безопасная работа с YAML:** При парсинге и записи файлов YAML всегда используйте C-расширения (`CSafeLoader`, `CSafeDumper`) для производительности. Обязательно добавляйте блок `try-except` с откатом (fallback) к стандартным безопасным загрузчикам (`SafeLoader`, `SafeDumper`), если C-расширения недоступны.
* **Изоляция подпроцессов (Docker):** Вызов команд Docker (`docker restart`) осуществляется через `subprocess.run` с передачей аргументов в виде списка (массива). Строго запрещено использование `shell=True`, чтобы избежать уязвимостей (shell-injection). Обязательно устанавливайте таймаут (например, `timeout=30`).
* **HTTP-взаимодействие (HTTPX):** При проверке состояния (health checks) необходимо явно указывать таймауты (например, `timeout=10.0`), чтобы избежать зависания MCP-сервера. Возвращаемые ошибки не должны приводить к крашу — сервер всегда должен отдавать валидный JSON-ответ (`success: false`).
* **Английский язык в коде и документации:** Все коммиты, основная документация (README.md, CONTRIBUTING.md, стандартный AGENTS.md), комментарии в коде и названия переменных должны быть написаны на качественном английском языке.

## 4. Советы для будущих ИИ-агентов
* **Соблюдайте роли и ведите журналы (Memory):**
  * **Sentinel (Безопасность):** Если вы выполняете задачи, связанные с безопасностью, ведите журнал критических находок в файле `.jules/sentinel.md` (не пишите туда рутинные логи). Формат названия PR: `🛡️ Sentinel: [Severity] Fix [vulnerability]` или `🛡️ Sentinel: [security improvement]`.
  * **Bolt (Производительность):** Для задач по оптимизации ведите журнал в `.jules/bolt.md`. Формат PR: `⚡ Bolt: [improvement]` с описанием What, Why, Impact и Measurement.
* **Понимание контекста:** Если что-то неясно, всегда проверяйте `ARCHITECTURE.md` — там подробно описаны процессы сериализации, проверки доступности API и управления контейнерами.
* **Приоритет пользователя:** Всегда следуйте прямым инструкциям пользователя, даже если они временно противоречат общим правилам (например, как создание этого файла на русском языке).
