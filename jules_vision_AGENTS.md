# Инструкции для ИИ-агентов (Видение Jules)

Добро пожаловать, агенты! Этот файл содержит ключевые инструкции, правила и советы для успешной работы в репозитории `searxng-mcp-control`.

## 1. Стек и зависимости
Проект представляет собой backend-ориентированный сервер MCP (Model Context Protocol) для управления SearXNG.
*   **Язык:** Python 3.10+
*   **Фреймворк:** FastMCP (для реализации протокола MCP).
*   **Ключевые библиотеки:**
    *   `mcp>=1.0.0`
    *   `pyyaml>=6.0` (Управление конфигурацией)
    *   `httpx>=0.24.0` (Health-чеки и запросы к API)
    *   `pytest`, `pytest-mock`, `pytest-asyncio`, `pytest-cov` (для тестирования)

## 2. Команды верификации
Всегда проверяйте свои изменения перед коммитом.
*   **Установка зависимостей (включая dev-инструменты):**
    ```bash
    pip install -e .[dev]
    ```
*   **Запуск тестов с проверкой покрытия:**
    ```bash
    python -m pytest tests/ --cov=searxng_mcp_control
    ```
    *Требование:* Покрытие тестами (coverage) должно быть **>95%** для всех новых функций и багфиксов!

## 3. Архитектурные особенности и правила кодинга
*   **Типизация и форматирование:** Обязательно использование строгих type hints (`typing`) и написание понятных docstrings.
*   **Парсинг YAML:** Для парсинга и дампа YAML *всегда* предпочитайте использование C-extensions из PyYAML (`CSafeLoader`, `CSafeDumper`). Обязательно реализуйте fallback-механизм с использованием стандартных безопасных лоадеров (`SafeLoader`, `SafeDumper`) в блоке `try-except` на случай, если C-extensions недоступны. Использование небезопасных `load` или `dump` категорически запрещено.
*   **Управление контейнерами (Docker):** Вызов команд Docker выполняется через `subprocess.run`.
    *   **Запрещено:** Использовать `shell=True`.
    *   **Обязательно:** Использовать массив аргументов (например, `["docker", "restart", ...]`).
    *   **Обязательно:** Устанавливать таймауты (например, `timeout=30`), чтобы избежать зависаний.
*   **Обработка ошибок:** Все инструменты MCP должны возвращать структурированные JSON-объекты (например, с полями `success: false` и `error: "описание"`). Не допускайте падений сервера при сетевых ошибках или таймаутах.
*   **Документация:** Вся документация, комментарии в коде и Pull Requests должны быть на качественном английском языке, за исключением особых запросов пользователя.
*   **Роли (Персоны):**
    *   **Sentinel (Безопасность):** При работе с задачами безопасности (устранение уязвимостей, улучшения безопасности) ведите журнал важных находок в файле `.jules/sentinel.md` (не пишите туда рутинные логи). Формат PR: `🛡️ Sentinel: [Severity] Fix [vulnerability]` или `🛡️ Sentinel: [security improvement]`.
    *   **Bolt (Производительность):** При задачах оптимизации ведите журнал в `.jules/bolt.md`. Формат PR: `⚡ Bolt: [improvement]`, в описании укажите What, Why, Impact и Measurement.

## 4. Советы для будущих ИИ-агентов
*   **Сначала читай, потом пиши:** Всегда начинай с анализа файлов `README.md`, `ARCHITECTURE.md`, `CONTRIBUTING.md` и `AGENTS.md`. Они содержат актуальную архитектуру системы.
*   **Тесты — твой друг:** Проект использует `pytest`. Изучи тесты в папке `tests/` — они показывают, как работают моки (особенно для HTTP-запросов и subprocess) и как проверяются различные edge cases (например, поврежденные YAML-файлы или ошибки сети).
*   **Проверяй за собой:** После создания или изменения файлов, обязательно прочитай их через `cat` или `read_file`, чтобы убедиться, что всё записалось верно. Никогда не полагайся на то, что команда "просто сработала".
*   **Контекст важнее памяти:** Если текущий запрос пользователя противоречит инструкциям в памяти (или этому файлу), **всегда выполняй запрос пользователя**. Память служит лишь для контекста ("почему"), а не как строгие рамки, отменяющие задачи пользователя.
